## Interface Audit — Blocking Gaps
The existing Phase modules cannot yet be connected by orchestration alone:

1. **Semantic candidate → Injector input**
   - `SemanticMapper.map_papers_to_manuscript()` returns `CitationCandidate` objects containing a target sentence and semantic metadata.
   - `CitationInjector.inject_candidates()` accepts only `(CitationPosition, MatchResult)` tuples with exact AST line/column coordinates.
   - No existing module converts a reviewed `CitationCandidate` into that positional injection plan. Implementing sentence search directly inside `ManuscriptWorkflow` would duplicate injection/AST logic and is outside orchestration-only scope.

2. **Persistent continuation data**
   - `WorkflowGate` persists only phase, gate name, approval, and history.
   - It does not persist the active Markdown artifact, pending keys, analyzed papers, semantic candidates, IF policies, table decisions, or report paths needed by a new CLI process after confirmation.

3. **Interactive values cannot enter through CLI**
   - The production CLI accepts `--confirm <gate>` but has no structured option for Body IF, Table IF, journal name, All Authors, or floating-reference decisions.
   - Gate approval alone cannot reconstruct the deterministic parameters required by later modules.

4. **Compile/export interface mismatch**
   - `JournalStyleManager` and `PandocCommandBuilder` support CSL modification and Crossref/citeproc command construction.
   - `DocxExporter.export_manuscript()` calls `PandocAdapter.convert_markdown_to_docx()` with only the bibliography and cannot receive the resolved CSL, All Authors choice, Crossref ordering, or link-citations setting.
   - There is no existing single compile result object for `ManuscriptWorkflow` to validate and pass to Phase 7.

These gaps require small, explicit interface additions to existing modules before Phase 2–7 can be safely wired. They must not be solved by temporary scripts or by reproducing the missing logic inside the Workflow.

## Interface Fix Applied
- Added `engine/candidate_adapter.py` to convert a uniquely located, already-approved semantic target into the existing Injector tuple format. Missing or repeated targets fail closed.
- Extended `WorkflowGate` with JSON-compatible context persistence and restart-safe restoration.

- Connected structured Phase 1 confirmation to Phase 2 and Phase 2 summary confirmation to Phase 3 through the same `ManuscriptWorkflow` state file.

- Connected Phase 4–7 to the existing Floating, Adapter/Injector/Crossref, DOCX compile, and Mapping modules.
- Added `--csl` and `--pandoc-path` routing to the production CLI and installed Skill template.

No semantic scoring, target selection, IF decision algorithm, citation injection algorithm, or Pandoc command-building algorithm was rewritten.

## Preflight UX Stabilization — 2026-08-19

### Root Cause
The unified Engine route was complete, but its interaction contract distributed
one runtime configuration across five sequential user-blocking gates:
`IF_CONFIRM`, `SUMMARY_CONFIRM`, `FLOATING_CONFIRM`, `INJECTION_CONFIRM`, and
`EXPORT_CONFIRM`. Summary review and injection preview were implemented as
mandatory user approvals even though they are deterministic validation
checkpoints once the user has authorized the run. Journal, author display, and
floating behavior were also collected late instead of before execution. The
Installed Skill mirrored that gate sequence, so a normal safe run could not
proceed automatically after one informed user decision.

### Minimal Fix Applied
- Added an optional `runtime_config`/`run_preflight()` route to the existing
  `ManuscriptWorkflow`; no second entry, Framework, or Phase was created.
- Added CLI `--preflight` and `--floating-policy keep|ask|expand` while retaining
  all old `--confirm` and persisted-gate compatibility routes.
- A complete Preflight now validates Body IF, Table IF, journal, All Authors,
  Floating policy, optional CSL, and optional Pandoc path before any write.
- The same Workflow automatically performs safe Mode C migration when required,
  then Phase 1 through Phase 7.
- `SUMMARY_CONFIRM` and `INJECTION_CONFIRM` remain recorded as approved internal
  validation states. `References_Summary.md` and the injection candidate preview
  are still generated, but no longer block normal Preflight execution.
- Floating `keep` records suggestions and continues; `ask` interrupts only when
  an actual expansion exists; `expand` applies the existing AI-marker expansion
  route without a second prompt.
- Legacy ambiguity/unsafe mapping, missing dependencies, ambiguous journal
  choice, floating `ask`, injection/export failures, and all existing Engine
  fail-closed results remain blocking.
- Updated the Installed Skill so it only presents one Preflight, collects the
  configuration, invokes `ManuscriptWorkflow --preflight`, displays genuine
  Safety Interrupts, and returns final outputs.

## Preflight Configuration Contract Stabilization — 2026-08-19

### Root Cause
The Preflight stored Body and Table IF selections separately, but Phase 3
forwarded only Body `disabled` through the old global `disable_if` switch.
Thus disabling Body IF disabled Table IF too, while disabling Table IF was not
applied. The runtime never resolved an explicit Profile before collecting the
Preflight, so the Skill could not obtain canonical recommendations. Finally,
UNKNOWN IF appeared in `IFGateReport.blocked` but was not a persisted Workflow
Safety Interrupt; its candidate could reach the injector.

### Minimal Fix Applied
- Extended the existing `BodyCitationIFGate.apply_runtime_policy()` interface
  with independent Body/Table enabled states. Its legacy global
  `disable_if` compatibility path remains unchanged.
- Added `IF_NOT_APPLIED` for an explicitly disabled *relevant* policy. A table
  decision therefore cannot reject a separate Body candidate for the same
  paper.
- Added `PolicyManager.resolve_profile()` and
  `ManuscriptWorkflow.get_preflight_defaults()`. Omitted selection explicitly
  resolves the existing `default` Profile; named profiles resolve their own
  canonical YAML recommendations. No recommendation values are duplicated.
- Added the structured `IF_UNKNOWN_REVIEW` Safety Interrupt. With an enabled
  policy, UNKNOWN IF is persisted for review and cannot proceed to injection;
  an explicit `approve` or `exclude` confirmation is required. With the
  relevant policy disabled, IF is not applied and UNKNOWN does not interrupt.
- Added `--profile`, `--preflight-info`, and `--if-unknown` to the same
  production CLI entry; no new entry, Phase, or Framework was introduced.
- Replaced the Installed Skill's user-facing Preflight with localized natural
  language templates. It queries Workflow-owned recommendations and maps
  choices to existing internal values only after the user responds.

### Regression Coverage

## Explicit Pandoc Path Through Phase 0 — 2026-08-19

### Root Cause
The Production Entry parsed and persisted `pandoc_path`, and Phase 6 used it
for export, but Phase 0 called `EnvironmentChecker.check_all()` without that
path. A valid user-supplied executable therefore failed whenever `pandoc` was
not on `PATH`.

### Minimal Fix Applied
- Extended the existing `EnvironmentChecker.check_all()` with an optional
  explicit Pandoc path. When provided, it verifies file existence, executes
  `<path> --version`, verifies the output identifies Pandoc, and reports that
  executable as available without changing Windows `PATH`.
- Explicit mode discovers `pandoc-crossref.exe` from the supplied Pandoc
  directory first, then preserves the existing `PATH` lookup fallback.
- Passed the validated Preflight `pandoc_path` to
  `ManuscriptWorkflow._validate_environment_and_inputs()` before Phase 0.
- Extended the existing read-only `--preflight-info` route to run Phase 0 with
  an explicit path before presenting configuration; it writes no workflow
  state and requires no Preflight answers.
- Phase 6 still receives and uses the same persisted `pandoc_path`.

## Explicit Pandoc Path Through DOCX Preparation — 2026-08-19

### Root Cause

`_prepare_markdown()` constructed `PandocAdapter()` without it. DOCX input
conversion then rediscovered Pandoc through `PATH` and failed before Mode C.

### Minimal Fix Applied
- Added an optional executable path to the existing `PandocAdapter`. With an
  explicit path it invokes that exact executable; an invalid explicit path does
  not fall back to `PATH`.
- Passed the same validated `pandoc_path` from Preflight into DOCX → Markdown
  preparation. The no-path route continues to use existing `PATH` discovery.
- The existing read-only `--preflight-info` route now performs that same
